# SLSC

这是一个本地日志辅助工具。它通过读取本机日志，显示本局物品、位置、进度、房间统计，并提供中文翻译、图片参考和名单覆盖等功能。

当前版本：`3.9.31`

## 主要功能

- 实时追踪本地日志并绑定对应的 VRChat 进程，识别本局开始、结束和数据加载；VRChat 多开且无法自动判断时，可在界面选择正在游玩的账号。
- 自动识别不同地图并切换对应数据面板，也可手动固定显示任一面板。
- 支持职业、Boss 阶段、伤害结算、DPS、受伤来源和击败数量统计。
- 支持 BackroomsVR 电闸与谐振锚点日志转模型 OSC，分别输出本局完成状态、Ready 和每秒心跳。
- 提供可手动开关的透明置顶桌面 HUD，使用 Windows 逐像素 Alpha 合成，默认纯白文字并支持自选字体颜色，背景透明度支持 `0%` 至 `100%`，并可选择显示内容、拖动缩放保存布局及恢复默认设置。
- 支持通过 VRChat Chatbox OSC 输出 Boss 当前锁定玩家，仅在 Boss 战期间显示，可选择完整提示或仅输出玩家名，可配置主机和端口，并兼容包含特殊 Unicode 字符的玩家名称；Boss 战结束或关闭输出时立即清除 Chatbox 文字。
- 支持 VRChat OSC 自动连跳；启用后仅在 Ecliptica 世界的非幕间阶段、VRChat 位于前台且按住空格时持续触发跳跃，幕间或按住任一 Windows 键时会自动暂停，并完整透传 `Win + 空格` 等系统快捷键。
- 同局实时伤害只显示仍在线且仍处于当前对局的玩家；玩家离开世界、结束对局或目标 VRChat 进程退出时会立即断开同步，异常断网则由服务端心跳超时清理。
- 启动时从最新日志尾部恢复当前对局，避免从旧日志头部回放造成 CPU 占用过高。
- 显示地图物品、玩家物品、中文名称、位置、锁房状态和颜色标记。
- 显示关键进度状态，以及本局资源和物品刷新统计。
- 支持本地翻译缓存、在线翻译更新、图片参考和图片资源更新。
- 支持赞助者名单覆盖，可在 `mitmdump` 系统代理模式和 `hosts + Caddy` 模式之间切换，并在停止时恢复对应网络设置。
- 支持单独覆盖 Demo Lobby 的 `Mega Patreon` 名称；只拦截该世界的 VRCLinking 数据地址，与原赞助者名单覆盖互斥，启用后重新进入世界即可生效。
- 支持单 exe 后台自动更新：有新版本时显示更新状态并自动下载替换。

## 下载和使用

从 GitHub Releases 下载最新版本后直接运行即可，不需要安装。

建议先启动 VRChat，再启动本工具。程序会把日志启动时间与 VRChat 进程启动时间对应起来，并优先锁定正在 Ecliptica 或 BackroomsVR 中的实例。若多个账号同时在这些世界且无法可靠判断，程序会提示手动选择；可在 Ecliptica 的“同局伤害同步”或 BackroomsVR 的“VRChat 日志实例”区域选择，选定的进程退出后会自动停止读取该日志。

## BackroomsVR 模型 OSC

进入目标世界后自动切换 BackroomsVR 面板，也可在面板选择中手动选择。启用“电闸 / 谐振锚点 OSC 状态输出”，默认发送到 `127.0.0.1:9000`，主机、端口及目标世界 ID 可保存修改。多开时使用面板内的“VRChat 日志实例”选择正在游玩的账号。

在 VRChat 开启 OSC，在已安装对应 MA 预制件的模型“后室位置”菜单中开启对应类别的位置显示和“仅未激活（OSC）”。过滤开关不会自动开启位置显示。本工具只输出固定名称的 32 个 `TBVR_BreakerOSCDone00` 至 `31`、5 个 `TBVR_ResonanceOSCDoneArea0` 至 `4`、两个 Ready 和一个共享心跳 Bool，共 40 个外部输入；参数名称保持固定，不进行 MA 私有重命名。

位置显示、过滤和“所有人可见”开关均默认关闭、不保存，由用户在模型菜单控制。默认只有佩戴者能看到图标；开启“所有人可见”后，允许显示该模型及相应效果的其他 PC 玩家可看到相同的最终图标集合，包括完成过滤和 OSC 失效回退结果。公开开关不会自动开启位置显示，关闭公开或对应类别的位置显示会隐藏远端图标。远端接收模型同步的最终可见状态，无需运行本工具，也不读取佩戴者的本地 OSC。Quest 独立运行不支持该 PC shader。

电闸采用 `recv` 的 `acceptedEpoch/acceptedMask` 或 `accept` 的 `epoch/new`；也支持 `allFlipped mask=0x... active=N` 全部完成记录，但必须先从 `[MM] @@@ OnDeserialization ON` 的进行中 Level 0 状态或 `[LevelActivator:Lvl 0] Activate seed=...` 确认当前局次，并验证十六进制掩码位数等于 active。该记录没有 epoch，缺少当前局次时不采用。锚点只采用混沌区域 `deserialize/owner-apply`。没有快照时保持未知，电闸完成数量不等于本局生成数量，锚点按五个区域映射。模型射线决定哪些本局实际位置显示，软件不把全部候选点当成本局目标。

2026-10-16 的实测日志中，电闸只有一次初始 `recv mask=0`，随后两局各有一次 `allFlipped`，没有逐个翻闸的 `recv/accept`。这种日志只能在全部完成时恢复电闸完成集合，无法逐个实时隐藏；界面的“已知完成”仅表示日志已提供的状态。锚点仍有逐步完成记录，可以继续按区域更新。若连锚点也不隐藏，请同时检查本工具的输出开关、VRChat 的 OSC 开关、目标模型中的 40 个固定参数、位置显示与过滤开关；启动日志的 `OSC enabled: False` 只说明启动时关闭，不能证明整场始终关闭。

后台从所选客户端日志开头分块重放，恢复到最后一次房间切换，再读取追加的完整 UTF-8 行；恢复期间不启用 Ready。比赛日志确认新 seed 时同时撤销两类旧状态并等待新快照，重复的同局日志保留已知状态；确认结算或返回大厅时撤销两类 Ready，拒绝迟到的旧局快照。换房、epoch 重置、文件截断、日志切换、读取失败及关闭输出也会撤销缓存，每秒完整重发状态并翻转心跳。正常退出会发送 Ready=false，程序崩溃时由模型约五秒的心跳超时回退。邪教雕像无完成状态输出。

默认世界 ID：`wrld_59030639-7913-4abe-b67e-b3b72746eac3`。自动测试覆盖状态解析、日志恢复和 UDP OSC 契约；正式 VRChat 模型中的图标过滤仍需实机联调。

## 自动更新

程序启动后会在后台检查 GitHub Releases 最新版本。无更新时不会显示更新区域；发现新版本后会在界面显示状态、自动下载新 exe，并在下载完成后使用临时 updater 替换原路径程序。

更新请求会优先使用 GitHub 镜像地址，全部失败后再访问 GitHub 原始地址。

## 开发环境

Windows PowerShell：

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python slashco.py
```

也可以不激活虚拟环境，直接使用：

```powershell
.\.venv\Scripts\python.exe slashco.py
```

## 测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

## 打包

```powershell
.\.venv\Scripts\pyinstaller.exe --clean --noconfirm slashco.spec
```

打包完成后主程序位于：

```text
dist
```

## GitHub Releases 发布

仓库只通过 `.github/workflows/release.yml` 的手动 `workflow_dispatch` 发布版本，不会因普通提交、推送或 Tag 自动发布。只有明确决定发布到 Releases 时，才输入 `RELEASE` 触发工作流；工作流会校验版本、运行测试、构建 EXE、核对附件摘要，然后发布为 Latest Release。

## 注意事项

- 本工具只依赖本地日志解析，不修改目标程序文件。
- 两种名单覆盖功能会临时修改系统代理，且不能同时启用；停止覆盖后会尝试恢复原代理配置。
- 开发环境运行主程序脚本时只检查和显示更新，不执行 exe 自替换。
- 若 GitHub Release 不存在或网络不可用，自动更新会静默失败或只记录日志，不影响主要日志监听功能。
